------------------------------------------------------------
1. OBJETIVO
------------------------------------------------------------
Hoje varios botoes da NnBim gravam parametros compartilhados
(Nn_*, LUM_*) nos elementos/Rooms, mas a criacao das tabelas
(Schedules) no Revit para visualizar/conferir esses dados ainda
e manual. A ideia e que cada botao, ao final do seu fluxo,
ofereca criar/atualizar a tabela correspondente automaticamente.


------------------------------------------------------------
2. DECISOES DE ARQUITETURA (confirmadas)
------------------------------------------------------------

a) Centralizado vs. descentralizado
   -> DESCENTRALIZADO. Cada ferramenta (Ambientes, Luminotecnico,
      Pranchas) ganha sua propria chamada de "Gerar/Atualizar
      Tabela" no final do proprio fluxo. Sem painel/botao novo
      dedicado a isso.

b) Onde entra no fluxo
   -> Como parte do fluxo existente. Ao final da execucao do
      botao, perguntar via forms.alert(..., yes=True, no=True):
      "Criar/atualizar tabela 'NnBim - X'?"

c) Idempotencia
   -> Procurar ViewSchedule existente por NOME. Se existir, NAO
      recriar do zero: apenas adicionar os campos que ainda nao
      estao no ScheduleDefinition (comparando por ParameterId).
      Se nao existir, criar via ViewSchedule.CreateSchedule().

d) Pre-requisito de parametros
   -> Reaproveitar garantir_parametros_compartilhados() (de
      lib/Snippets/_shared_parameters.py) antes de montar a
      tabela, garantindo que os parametros Nn_*/LUM_* estejam
      criados e vinculados a categoria certa.

e) Layout dos campos
   -> Campos FIXOS pre-definidos no codigo (lista por tabela,
      ver secao 4). Alem disso, um botao/janela "Adicionar mais
      parametros" permite ao usuario incluir campos extras na
      tabela depois de criada.


------------------------------------------------------------
3. MODULO COMPARTILHADO NOVO
------------------------------------------------------------
Arquivo: lib/Snippets/_schedules.py

Funcao principal:

    def criar_ou_atualizar_tabela(doc, nome_tabela, categoria,
                                   campos_fixos, multi_categoria=False):
        """
        :param categoria: BuiltInCategory (ignorado se multi_categoria=True)
        :param campos_fixos: lista de itens, cada um:
               - BuiltInParameter  -> campo nativo do Revit
               - str               -> nome de parametro compartilhado/projeto
                                       (ex.: "Nn_Largura", "LUM_FU")
        :return: (schedule, adicionados, nao_encontrados)
        """

Logica:
  1. Procura ViewSchedule existente com Name == nome_tabela via
     FilteredElementCollector(doc).OfClass(ViewSchedule).
  2. Se nao existir:
       cat_id = ElementId.InvalidElementId se multi_categoria
                else ElementId(categoria)
       schedule = ViewSchedule.CreateSchedule(doc, cat_id)
       schedule.Name = nome_tabela
  3. definition = schedule.Definition
     schedulable = definition.GetSchedulableFields()
     Monta dicionario de busca:
       - se sf.ParameterId.IntegerValue < 0 (nativo):
             chave = BuiltInParameter(sf.ParameterId.IntegerValue)
             (evita depender do idioma do Revit)
       - senao (parametro compartilhado/projeto):
             chave = sf.GetName(doc)  (ex.: "Nn_Largura")
  4. Para cada item em campos_fixos:
       - se chave existe no dict E ParameterId ainda nao esta
         em algum definition.GetField(i) -> definition.AddField(sf)
       - senao -> entra em nao_encontrados (parametro ainda nao
         vinculado, ou campo nao existe para essa categoria)
  5. Roda dentro do ef_Transaction do script chamador.
     Quem chama decide se exibe aviso sobre nao_encontrados.
